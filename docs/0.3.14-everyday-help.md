# Pippa 0.3.14: durable everyday help

Pi remains Pippa's agent core: it interprets requests, plans steps, chooses tools, asks questions and solves problems across tools. This release adds a native file-preparation tool and durable execution state around that core. It adds no replacement planner or independent agent loop, and saved conversation text does not authorize autonomous background work.

## Product boundary

- File preparation begins with an explicit request on chosen PDFs or photos. In the tray, the person reviews source order, quality and optional size limit before execution. In chat, Pi supplies ordered paths and those same options to `prepare_files`; both paths use the same conversion, verification and durable record. Originals are never modified. This tool has no send/upload step.
- `prepare_files` uses the existing native turn, cancellation and receipt mechanisms. It is exposed in Pi's standard agent mode, hidden and blocked in draft-only mode, and verified during native tool discovery. General Pi planning and its existing tool capabilities remain unchanged. A chat card is built from verified native output, not from model text.
- Saved requests retain source identity, order and run state. Relaunch restores the request or verified result; interrupted work never executes merely because its record was recovered.
- The morning overview is off by default. A person chooses exact EventKit calendar/list identifiers, weekdays and local time. New calendars and lists remain unselected. It reads only Calendar and Reminders through a dedicated read-only adapter.
- The routine runs only while Pippa is open. A current-day catch-up is bounded to four hours; missed days are not replayed. The record distinguishes unreadable sources from empty sources.
- Notifications are separately opt-in, requested only by a settings action, and contain generic text. Pause, source changes and deletion invalidate pending asynchronous work.

## Why this fits a 16–24 GB Mac

The shipping default remains Qwen3.5 9B Q4: a 16,384-token context on the 16 GB tier and 32,768 on the 24 GB tier. A bigger context is not a stronger planner. The older local comparison recorded 17 complete, 12 partial and one unsuccessful agentic run out of 30 for the thinking variant; this is historical synthetic evidence, not an acceptance rate for the current app. See [the measurement and its limitations](measurements/model-compare/README.md).

Native code performs file conversion, schedule decisions, source reads, deduplication and verification. The tray action and opted-in morning routine do not need an LLM call. Chat stays a Pi conversation: the local model chooses when and how to use the file tool, then continues with its result. Apple Foundation Models remains useful for existing bounded short-text actions. No default model or inference tuning changes in this release. Larger quantized candidates require a current full-runtime comparison with task correctness, time and memory pressure measured together.

## Persistence and failure handling

`DurableJobStore` uses SQLite transactions and revision/run tokens. Source content identities and artifact ownership are checked. Completion is published only after persistent result storage succeeds. Artifact files live in Application Support, outside the expiring tool-result cache. Inbox cleanup retains inputs referenced by saved jobs and skips cleanup if those references cannot be read. Dismissed artifacts are pruned only after a grace period, when unchanged and no longer referenced by a conversation or the tray. Live records and completed results are not swept by this cleanup.

Within one Pi turn, repeating the same normalized paths and quality/size choices returns the verified result for the originally captured inputs. It never silently reruns conversion after source edits. A new task can capture new inputs. Undo preserves outputs that someone has edited after preparation.

The morning routine has its own settings, occurrence claim and generation guard. It never receives Pi's broader interactive tool set. Facts come from the chosen native sources; there is no model-generated urgency, obligation, calendar edit or reminder creation.

`scripts/check-everyday-help.sh` runs isolated real controllers with synthetic sources and no model. It covers reordered duplicate filenames, exact artifact readback, failed Save, restart restoration, Stop, Pi receipt/card mapping, unavailable or edited results, morning source scope, pause/delete races and opt-in defaults. Screenshots cover English and German, including native segmented quality controls and compact size menus.

The pinned Pi tests exercise its actual MCP connector with a scripted provider. They confirm that enum-only quality/size schemas reach the provider and that ordered paths and chosen values survive dispatch. Prompt and MCP declaration budgets remain 6,400 and 3,100 characters, and both checks pass. These are protocol and execution checks, not a new benchmark of local-model planning quality.

The macOS 15 acceptance workflow includes the same app flows and uploads their reports and screenshots. Check the PR's CI and compatibility jobs before merging. Before a release, verify the signed package, notarization and update artifacts separately; this implementation's native run skipped the optional real-payload installer check because `PIPPA_PI_PAYLOAD` was unset.

Physical 8/16 GB hardware, a fresh TCC profile and private Calendar/Reminders account behavior have not been certified by these fixtures. Native API compilation and injected-reader tests do not substitute for those checks. No new end-to-end Qwen planning benchmark or 16 GB memory-pressure certification is claimed.
